## 1. 本版边界

V1实现固定Decode-first、固定每请求Chunk、全局Token Budget以及同一Step的一次完整模型前向。共享QKV投影/输出投影/MLP，在各层内分别调用Decode和Prefill Attention，按Decode-first扁平布局拼接结果。不是先跑完整Decode模型再跑完整Prefill模型。

保留原`LLMEngine/Scheduler/ModelRunner`作为V0基线。新入口为`MixedLLMEngine`和`benchmarks.v1.run`。不实现Slack、Hysteresis、Aging、水位策略、量化KV或自研Attention Kernel；这些仍属于V2之后。

## 3. 必须理解的语义

- `num_computed_tokens`复用`num_cached_tokens`存储，不保留两份可写进度。
- 中间Chunk只写KV，不采样；末Chunk与Decode每请求每Step最多输出一个Token。
- `postprocess`在GPU执行返回后提交进度和Prefix Hash；无采样行时显式同步。
- 抢占释放页引用并重置computed，保留生成历史。实际Recompute由已执行区间的交集统计，不用高水位差代替。
- Prefix缓存页只读，当前Step的新写入Slot不得重复。当前BlockManager仍为整个Prompt预留页，不把“分块计算”误称为“按Chunk增量分配Prompt显存”。
- 部分Prefill继续留在waiting；有界扫描绕过不可分配的队首，以免已分配部分请求被卡死。这不是V4的Aging策略。
- Mixed/Prefill用Eager；纯Decode仅在已有Graph bucket可容纳时回放，否则Eager。不承诺Mixed Graph。
- TP传递完整BatchMetadata，不依赖旧Sequence省略历史Token的序列化；1MiB共享内存超限显式报错。跨rankKV容量取最小值，TP=1不调用多余collective。

## 4. 数值验收不能偷换口径

标准正确性集使用`--prompt-kind natural`：人工构造的语言Token序列，仍是合成负载，不是ShareGPT。`--prompt-kind random`保留旧随机ID压力测试，不能删除或掩盖其失败结果。

Greedy完整输出和固定历史Top-1是独立检查。候选与原引擎改变Batch/Attention/Graph路径后可能有BF16数值差异；随机无语义输入可出现Top-1并列，早期一处Token分歧会放大为整条输出分歧。不能因此宣称通用100% Token一致，也不能跳过KV地址和状态验证。

`reference`默认`--numerical-policy strict`，要求逐元素`allclose(atol=0.15,rtol=0.03)`及Top-1一致。测试脚本显式选择`bf16`：Top-1必须一致、误差有限，且满足原allclose，或同时满足relative-L2≤0.02、cosine≥0.999、max-absolute≤0.5。全部门槛与`strict_allclose_passed`写入报告；这只是本模型初版工程门槛，不是量化质量门槛或数学证明。门槛变更须另存结果并说明依据，不允许看到失败就反复放宽到通过。

已观察到原引擎自身Prefill/Decode路径超出逐元素容差，也观察到随机测试出现并列Logits。原始失败目录保留。标准集通过不覆盖随机压力集，更不意味着性能有提升。

## 5. 基础与GPU命令

所有命令在服务器执行，默认使用已有`.venv`和本地4B权重。不要同时启动多个引擎：上游使用固定端口2333和共享内存名称。

```bash
cd /home/lq/project/SLO-Aware-LLM-Serving-Engine
source scripts/env_qwen3_4b.sh
bash scripts/test_v0.sh --cpu
bash scripts/test_v1.sh --cpu

CUDA_VISIBLE_DEVICES=0 bash scripts/test_v1.sh --gpu --tp 1
CUDA_VISIBLE_DEVICES=0 bash scripts/test_v1.sh --gpu --tp 1 --graph
CUDA_VISIBLE_DEVICES=0,1 NCCL_IB_DISABLE=1 NCCL_DEBUG=INFO \
  bash scripts/test_v1.sh --gpu --tp 2
CUDA_VISIBLE_DEVICES=0,1 NCCL_IB_DISABLE=1 NCCL_DEBUG=INFO \
  bash scripts/test_v1.sh --gpu --tp 2 --graph
```

每条GPU命令依次执行mixed/prefix/preempt三类候选与原引擎参考，强制抢占用2个KV Block。退出码必须为0，终端末行应有`V1 correctness checks passed`。`report.json`记录Greedy、Logits、真正Mixed Step、抢占/重算和Graph回放。模型Python hook额外检查：Eager Step仅一次完整前向，Graph Step无额外Python模型前向。

本机TP=2仍需`NCCL_IB_DISABLE=1`绕过已复现的IB/RoCE崩溃；不将其写入全局环境，也不能据此推断所有服务器均需禁用IB。

## 6. 在线端到端烟雾

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/test_v1_online.sh
# 单卡通过后，可分别验证以下配置，不要并行：
CUDA_VISIBLE_DEVICES=0 bash scripts/test_v1_online.sh --graph
CUDA_VISIBLE_DEVICES=0,1 NCCL_IB_DISABLE=1 NCCL_DEBUG=INFO \
  bash scripts/test_v1_online.sh --tp 2
```

脚本先验证4个语言fixture请求的native/minimal/full模式，每轮重算审计并对照原引擎Greedy；再使用同一Poisson Trace分别运行原调度与V1，审计并输出`comparison.json`。烟雾窗口只有2秒Warmup+8秒测量，不能据此填写简历加速比、容量或SLO收益。

`native`没有逐Token时间；`minimal`有逐Token时间但无细粒度Step日志；`full`额外记录Mixed phase、Prefill Tokens、KV占用、抢占/重算、Graph模式。中间Chunk不计为输出Token。

## 7. 完整矩阵：完成实现不等于完成全部验收

CPU已覆盖Batch×Chunk全部16种组合。GPU完整矩阵、重复轮次和正式在线实验需独立运行，不能用单轮默认Batch=8/Chunk=256替代。

```bash
# 单卡Eager的16组，每组重复3轮；然后分别增加--graph或改TP=2重跑。
for batch in 1 2 8 32; do
  for chunk in 256 512 1024 2048; do
    CUDA_VISIBLE_DEVICES=0 bash scripts/test_v1.sh --gpu --tp 1 \
      --batch "$batch" --chunk "$chunk" --token-budget 4096 --repeats 3 || break 2
  done
done

# 独立随机ID压力组；失败需分析，不能删除或记为已通过。
CUDA_VISIBLE_DEVICES=0 bash scripts/test_v1.sh --gpu --tp 1 \
  --graph --prompt-kind random
```

正式在线对照建议复用V0粗扫的Trace，或重新生成30秒Warmup+120秒测量、输出64 Token、三个seed。原引擎与V1统一TP/Graph/Budget/max-seqs/显存/Drain。用`benchmarks.v0.validate_results`审计每个目录，再用`compare_runs`对照；只改变算法和每请求Chunk。RPS=2是绝对到达率，不称0.8×饱和负载，V0粗扫尚未精确确定稳定容量。

```bash
# 比较已完成的两个目录，先分别审计：
"$V0_PYTHON" -m benchmarks.v0.validate_results --run-dir /absolute/path/legacy
"$V0_PYTHON" -m benchmarks.v0.validate_results --run-dir /absolute/path/mixed
"$V0_PYTHON" -m benchmarks.v1.compare_runs \
  --baseline /absolute/path/legacy --candidate /absolute/path/mixed
```

`prefill_overlap_itl`只统计Token结束时刻位于测量窗口、且与含Prefill的Step时间重叠的ITL，报告count/max/P99。时间重叠不是因果证明；还要看TTFT/吞吐/SLO、重复轮次与Profiler，不能孤立用最大ITL宣称整体优化。
