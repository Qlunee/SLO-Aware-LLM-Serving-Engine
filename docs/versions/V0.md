## 二、环境与量化探测

默认服务器Python3.13不满足上游约束。项目.venv使用Python3.11.16并继承hgemm的system-site-packages；用户已完成依赖安装，目前PyTorch2.11.0+cu128、Triton3.6.0、Transformers4.57.6、FlashAttention2.8.3.post1、xxhash均已通过前置检查。原GEMM环境未由本项目修改。后续环境安装/升级命令仍由用户执行。

仅在重建环境或依赖缺失时参考下列安装命令；当前环境无需重复安装：

```bash
cd /home/lq/project/SLO-Aware-LLM-Serving-Engine
source .venv/bin/activate
python -m pip install 'transformers==4.57.6' xxhash einops ninja packaging
CUDA_HOME=/usr/local/cuda-12.8 MAX_JOBS=4 NVCC_THREADS=2 FLASH_ATTN_CUDA_ARCHS=80 python -m pip install --no-build-isolation 'flash-attn==2.8.3.post1'
export V0_PYTHON=/home/lq/project/SLO-Aware-LLM-Serving-Engine/.venv/bin/python
```

FA在本机已完成导入及Qwen3-4B推理验证。重建时可能退回源码编译，耗时较长。CUDA_HOME选12.8以匹配torch2.11+cu128；仅构建SM80架构的FA可在SM86上运行。不要安装到hgemm本身。本.venv继承其PyTorch，hgemm升级也会影响本项目，正式复现实验需记录pip freeze及实际环境摘要。


输出路径不允许覆盖，重复执行请换名。量化探测不依赖flash-attn/xxhash，可以先独立执行。E4M3FN的254个有限编码、ties-to-even、饱和和负零先由CPU验证。GPU报告保留支持/失败路线，不能通过删去不支持路线伪造全通过。

## 三、真实推理回归

先source scripts/env_qwen3_4b.sh，统一载入解释器、4B目录和冻结revision。workload/run/sweep与test_v0.sh的默认模型均来自configs/qwen3_4b.json；无需重复填写模型参数。支持显式覆盖；自定义目录须同时提供真实revision，不能填写latest。本地4B已作为正式验收模型，无需另备0.6B。

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/test_v0.sh --gpu --tp 1 --repeats 3
CUDA_VISIBLE_DEVICES=0 bash scripts/test_v0.sh --gpu --tp 1 --repeats 3 --graph
CUDA_VISIBLE_DEVICES=0,1 NCCL_DEBUG=INFO NCCL_IB_DISABLE=1 bash scripts/test_v0.sh --gpu --tp 2 --repeats 3
```

脚本先CPU/前置检查，再量化探测、全零到达native/minimal/full、各自原generate正确性对照，最后Poisson烟雾及指标审计。token-budget=256且输入含512，特意覆盖中间Prefill Chunk不产出Token。每个子实验日志单独保存；首个失败停止，已有产物保留。--repeats 1只用于快速烟雾。

本机默认IB/RoCE路径首次AllReduce段错误。最小NCCL对照及真实推理验证NCCL_IB_DISABLE=1可绕过，GPU间仍走P2P/CUMEM；拓扑显示NV4。不要把该问题误判为FP8编译失败，也不要默认禁用P2P或重装PyTorch。此变量需随本机TP=2实验保留并归档，不能推断其他服务器也必须设置。

## 四、正式容量扫描

```bash
V0_CAPACITY_DIR="$(mktemp -d "$PWD/results/raw/v0-capacity.XXXXXX")"
CUDA_VISIBLE_DEVICES=0 "$V0_PYTHON" -m benchmarks.v0.sweep --rates 0.5 1 2 4 8 --seeds 41 42 43 --warmup-s 30 --measurement-s 120 --drain-s 60 --input-lengths 256 1024 2048 --output-tokens 64 --max-model-len 4096 --max-num-seqs 64 --token-budget 4096 --gpu-memory-utilization 0.8 --observation full --sampler greedy --tp 1 --graph --out "$V0_CAPACITY_DIR/tp1_graph"
```

这只是初始RPS网格，要依真实结果继续细扫；不能认为8req/s就是饱和。30秒Warmup需检查是否排除首轮开销；2秒Poisson仅为烟雾，不能作为稳态证据。控制Graph/显存/输入输出/TP配置，在同Trace上比较三种observation，再计算均值、离散性和观测开销。更换模型或配置必须重测饱和点。4K基线不等于模型原生Context上限；8K/16K实验须显式设置max-model-len并检查KV容量。
